# GitHub Infrastructure Setup Summary

This repository already contains a full `.github/` automation stack. The most
important current-state facts are below.

## What exists today

- structured issue forms for feeds, docs, CLI, workflows, bugs, and feature requests
- a shared PR template
- deterministic GitHub Actions YAML workflows
- additive gh-aw source files stored as `.md` pilots on top of the live YAML workflows
- canonical feed-submission parsing via `.github/scripts/feed_submission_to_source.py`
- extracted workflow evidence for the distillation layer under `reports/github/...`,
  including catalog summaries and issue-scoped feed-submission snapshots

## Safety posture summary

- feed submission validation is separate from approval
- approval opens a pull request instead of mutating `main`
- auto-fix only runs on same-repo pull requests
- release publishing uses GitHub OIDC trusted publishing
- experimental gh-aw pilots remain non-canonical, read-only-first distillations until adopted

## Useful local commands

```bash
uv run python data/validate_data_assets.py
uv run pytest
pnpm --dir apps/web build
pnpm --dir apps/web lint:links
```

## Feed-submission dry run

```bash
uv run python .github/scripts/feed_submission_to_source.py \
  --event-path reports/feed-submission-event.json \
  --output-source reports/parsed_feed.json \
  --output-summary reports/parsed_feed_summary.md
```
