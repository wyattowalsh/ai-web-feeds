AI Web Feeds supports two practical deployment profiles.

## Choose a Deployment Profile

| Profile       | What runs                                   | When to use it                                                          |
| ------------- | ------------------------------------------- | ----------------------------------------------------------------------- |
| Web only      | Next.js web app                             | Default choice for browsing feeds, docs, downloads, explorer, and stats |
| Web + backend | Next.js web app plus `ai_web_feeds.web_api` | Use when you need recommendations and backend-backed analytics          |

## Web-Only Deployment

The web-only setup is enough for most of the public product.

It supports:

- `/feeds`
- `/explorer`
- `/downloads`
- `/stats`
- `/docs`
- `/llms.txt` and `/llms-full.txt`

### Build and run the web app

```bash
cd apps/web
pnpm install
pnpm build
pnpm start
```

## Shared Runtime Preparation

Even in the web-only profile, the standalone app expects generated data artifacts.

### Install the Python workspace

```bash
uv sync
```

### Build the article library

```bash
uv run ai-web-feeds corpus refresh
```

That command populates runtime data and writes `data/articles.generated.json` for the web app.

## Optional Backend Deployment

Add the backend only when you need live server-backed features.

### Start the backend

```bash
uv run uvicorn ai_web_feeds.web_api:app --host 127.0.0.1 --port 8001
```

### Point the web app at it

```bash
BACKEND_URL=http://127.0.0.1:8001
```

With `BACKEND_URL` configured, the web app can enable:

- recommendations
- analytics summaries and exports
- write-side analytics logging

## Environment Notes

Common variables:

```bash
AIWF_ADMIN_PASSWORD=change-me
AIWF_ADMIN_SESSION_SECRET=replace-with-a-long-random-secret
# BACKEND_URL=http://127.0.0.1:8001
```

## Verification Checklist

- the web app builds with `pnpm build`
- `data/articles.generated.json` exists and is current
- the public routes load without a backend
- if `BACKEND_URL` is set, `/recommendations` and `/analytics` stop showing their unavailable states
