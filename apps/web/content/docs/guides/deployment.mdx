AI Web Feeds supports two practical deployment profiles.

## Choose a Deployment Profile

| Profile       | What runs                                   | When to use it                                                            |
| ------------- | ------------------------------------------- | ------------------------------------------------------------------------- |
| Web only      | Next.js web app                             | Default choice for browsing feeds, docs, OPML export, explorer, and stats |
| Web + backend | Next.js web app plus `ai_web_feeds.web_api` | Use when you need recommendations and backend-backed analytics            |

## Web-Only Deployment

The web-only setup is enough for most of the public product.

It supports:

- `/feeds`
- `/explorer`
- `/api/exports/opml`
- `/stats`
- `/docs`
- `/llms.txt` and `/llms-full.txt`

### Build and run the web app

```bash
cd apps/web
pnpm install
pnpm build
pnpm start
```

## Shared Runtime Preparation

Even in the web-only profile, the standalone app expects generated data artifacts.

### 1. Create Environment File

```bash
cp .env.example .env
```

### 2. Configure Environment Variables

For the password-protected admin observability flow, this is the minimum local setup:

```bash
AIWF_ADMIN_PASSWORD=change-me
AIWF_ADMIN_SESSION_SECRET=replace-with-a-long-random-secret
```

Optional local overrides:

```bash
AIWF_TELEMETRY_DIR=../../data/telemetry
# AIWF_TELEMETRY_SALT=replace-with-a-stable-hashing-salt
# BACKEND_URL=http://127.0.0.1:8001
```

You do not need email or SMTP variables for the simple admin telemetry setup.

`BACKEND_URL` is optional. It is only required if you want live analytics and personalized recommendations. Without it:

- `/feeds`, `/docs`, `/explorer`, and `/stats` still work
- `/analytics` shows an intentional unavailable panel
- `/recommendations` shows an intentional unavailable panel

## Docker Compose

The repository ships a two-service compose setup that matches the codebase as it exists today:

- `web`: the standalone Next.js application on port `3000`
- `monitor`: the Python monitoring/WebSocket service on port `8000`

Start both services with:

```bash
docker compose up --build
```

Notes:

- The compose stack no longer assumes a separate nginx container or a generic
  Python HTTP backend that the repository does not currently assemble.
- `BACKEND_URL` remains optional. Set it only if you are running the separate
  ai-web-feeds backend HTTP surface for analytics and recommendations.
- `NEXT_PUBLIC_WEBSOCKET_URL` is optional. Local development defaults to
  `http://localhost:8000`; deployed environments default to same-origin WebSocket
  connections unless you set this variable to an explicit monitor/WebSocket URL.
- The monitor service uses the default SQLite database at
  `sqlite:///data/ai-web-feeds.db` unless you override `DATABASE_URL`.

## Shared Python Runtime Setup

The standalone web app expects two things for the full reader and search experience:

1. the checked-in source catalog under `data/`
2. a generated article corpus at `data/articles.generated.json`

You do **not** need a Python HTTP backend for `/feeds`, `/api/articles`, or GET-based search. You do need the Python runtime when you want to poll feeds and rebuild the corpus artifact.

### 1. Install Dependencies

```bash
uv sync
```

### Build the article library

```bash
uv run ai-web-feeds corpus refresh
```

That command populates runtime data and writes `data/articles.generated.json` for the web app.

## Optional Backend Deployment

Add the backend only when you need live server-backed features.

### Start the backend

```bash
uv run uvicorn ai_web_feeds.web_api:app --host 127.0.0.1 --port 8001
```

### Point the web app at it

```bash
BACKEND_URL=http://127.0.0.1:8001
```

With `BACKEND_URL` configured, the web app can enable:

- recommendations
- analytics summaries and exports
- write-side analytics logging

## Environment Notes

Common variables:

```bash
AIWF_ADMIN_PASSWORD=change-me
AIWF_ADMIN_SESSION_SECRET=replace-with-a-long-random-secret
# BACKEND_URL=http://127.0.0.1:8001
```

## Verification Checklist

- the web app builds with `pnpm build`
- `data/articles.generated.json` exists and is current
- the public routes load without a backend
- if `BACKEND_URL` is set, `/recommendations` and `/analytics` stop showing their unavailable states
