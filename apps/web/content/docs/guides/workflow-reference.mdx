# Workflow Quick Reference

Use this page for the most common GitHub CLI and local verification commands.

## Trigger active workflows manually

```bash
gh workflow run validate-all-feeds.yml
gh workflow run process-feeds.yml
gh workflow run release.yml -f version=0.1.0

gh run list --workflow=validate-all-feeds.yml
gh run watch <run-id>
gh run view <run-id> --log
```

## Local mirrors

```bash
uv run python data/validate_data_assets.py
uv run pytest
uv run ai-web-feeds validate all --strict
uv run ai-web-feeds export all --input data/feeds.yaml --output-dir reports/exports
pnpm --dir apps/web build
pnpm --dir apps/web lint:links
```

## Feed submission dry run

```bash
uv run python .github/scripts/feed_submission_to_source.py \
  --event-path reports/feed-submission-event.json \
  --output-source reports/parsed_feed.json \
  --output-summary reports/parsed_feed_summary.md
uv run python data/validate_data_assets.py
```

## Deterministic summary artifacts

- `reports/github/catalog/feed-processing-summary.json`: extracted machine-readable
  output for the main feed processing pipeline
- `reports/github/feed-submissions/issue-<number>/normalized-source.json`:
  extracted normalized feed-submission payload
- `reports/github/feed-submissions/issue-<number>/validation-summary.md`:
  extracted maintainer-facing submission summary
- `reports/github/feed-submissions/issue-<number>/snapshot-manifest.json`:
  extracted provenance and freshness metadata for the submission snapshot
- `reports/github/feed-submissions/issue-<number>/feed-submission-validation-summary.json`:
  extracted machine-readable output for the validated feed-submission path
- gh-aw source files should consume these additive `reports/github/...` artifacts
  instead of becoming the canonical mutation path

## Safety reminders

- only `.yml` files in `.github/workflows/` are active workflows
- `.md` files in `.github/workflows/` are gh-aw source files: additive, non-executable distillations layered on top of the live YAML workflows
- gh-aw pilots should stay read-only or report-only until there is an explicit adoption plan
- `approved` should only be applied after a submission is already `validated`
- release publishing uses OIDC trusted publishing via `release.yml`
