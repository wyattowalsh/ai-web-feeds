This guide gets you from a fresh clone to a working ai-web-feeds environment using the repository-required tooling: `uv` for Python and `pnpm` for the web app.

## Prerequisites

Before you begin, ensure you have:

- Python 3.13 or higher
- Node.js 20+
- [uv](https://github.com/astral-sh/uv)
- [pnpm](https://pnpm.io/)
- Git

```bash
uv sync

pnpm install
cd ../..

mkdir -p data
uv run python - <<'PY'
from ai_web_feeds.storage import DatabaseManager
db = DatabaseManager('sqlite:///data/ai-web-feeds.db')
db.create_db_and_tables()
PY

uv run ai-web-feeds enrich all \
  --input data/feeds.yaml \
  --output data/feeds.enriched.yaml \
  --schema data/feeds.enriched.schema.json \
  --database sqlite:///data/ai-web-feeds.db
```

## Quick Start

### 1. Validate the Catalog

Run the built-in HTTP validation pass against the canonical feed list:

```bash
uv run ai-web-feeds validate http
```

### 2. Regenerate Enriched Metadata

```bash
uv run ai-web-feeds enrich all \
  --input data/feeds.yaml \
  --output data/feeds.enriched.yaml \
  --schema data/feeds.enriched.schema.json \
  --database sqlite:///data/ai-web-feeds.db
```

### 3. Generate Reader Exports

```bash
uv run ai-web-feeds opml all --output data/all.opml
uv run ai-web-feeds opml categorized --output data/categorized.opml
```

### 4. Launch the Docs App

```bash
cd apps/web
pnpm dev
```

## Working With `data/feeds.yaml`

The repository already includes a curated catalog in `data/feeds.yaml`. When you want to add or edit sources, update that file first and then rerun the enrichment and validation commands above.

Example entry:

```yaml
sources:
  - id: my-custom-feed
    feed: https://example.com/feed.xml
    title: My Custom Feed
    source_type: blog
    topics: [llm]
    tags: [custom]
```

## Troubleshooting

### Missing Tooling

If `uv` or `pnpm` is missing, install them before continuing. The repository policy explicitly avoids bare `python`, `pip`, `npm`, and `yarn` workflows.

### Reset the Local SQLite Cache

```bash
bash scripts/setup.sh
```

If you need a completely fresh local cache, remove `data/ai-web-feeds.db` and run the setup script again. The codebase still recognizes the legacy `data/aiwebfeeds.db` filename if an older local install already exists.

## Current Web Surfaces

Once `pnpm dev` is running, these are the routes worth checking first:

| Route        | Status | What to expect                                                                                        |
| ------------ | ------ | ----------------------------------------------------------------------------------------------------- |
| `/feeds`     | Live   | Primary catalog and subset-selection surface for source-type, topic, verification, and text filtering |
| `/search`    | Live   | Local-first source and article search with URL-driven filters                                         |
| `/reader`    | Live   | Built-in reader over recent posts, including saved/starred local views                                |
| `/explorer`  | Live   | Graph + table catalog browser for topics and feeds                                                    |
| `/downloads` | Live   | Full-catalog OPML/JSON downloads plus the optional OPML preview and merged timeline                   |
| `/analytics` | Live   | Local analytics for source counts, topic momentum, freshest sources, and velocity                     |
| `/docs`      | Live   | Fumadocs site, including `/llms.txt`, `/llms-full.txt`, and markdown routes                           |

## Recommended Next Steps

1. Start with the feed catalog at `/feeds` to define the slice you care about.
2. Move to [Search & Discovery](/docs/features/search) or open `/search` when you need text retrieval across sources or recent articles.
3. Use the [Reader](/reader) to browse recent posts from the same catalog slice.
4. Review the [OPML Viewer](/docs/guides/opml-viewer) guide before exporting a full bundle from `/downloads` or a filtered bundle from `/feeds`.
5. Use the [Data Explorer](/docs/guides/data-explorer) to inspect the catalog structure.
6. Read [Contributing](/docs/development/contributing) before opening a docs or code change.
