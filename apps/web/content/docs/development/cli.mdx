# CLI Usage

`ai-web-feeds` is the primary command-line entrypoint for the repository. The
legacy `aiwebfeeds` binary still exists as a compatibility alias, but the live
repo defaults to the hyphenated command name in scripts, docs, and examples.

<Callout type="info" title="Invocation pattern">
  Run the CLI from the repository root with <code>uv run ai-web-feeds ...</code> so the workspace packages resolve consistently.
</Callout>

## Install and smoke test

```bash
uv sync
uv run ai-web-feeds --help
uv run ai-web-feeds process --help
```

## Top-level command surface

| Command     | Purpose                                                                | Representative subcommands                                                                                                |
| ----------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `process`   | End-to-end catalog pipeline                                            | root command with `--skip-validation`, `--skip-enrichment`, `--export/--no-export`                                        |
| `load`      | Load catalog data into the runtime database                            | `from-yaml`, `all`                                                                                                        |
| `validate`  | Validate catalog documents, topic references, URLs, and health reports | `feeds`, `topics`, `references`, `all`, `http`, `report`                                                                  |
| `enrich`    | Enrich feed metadata and write derived assets                          | `all`, `one`                                                                                                              |
| `export`    | Export YAML catalogs to JSON and OPML                                  | `json`, `opml`, `all`, `csv`                                                                                              |
| `opml`      | Generate reader-oriented OPML files from stored feed sources           | `all`, `categorized`, `filtered`                                                                                          |
| `stats`     | Show high-level database statistics                                    | `show`                                                                                                                    |
| `test`      | Run repository pytest suites through a CLI wrapper                     | `all`, `unit`, `integration`, `e2e`, `coverage`, `quick`, `file`, `debug`, `markers`                                      |
| `analytics` | Query runtime analytics snapshots and CSV exports                      | `summary`, `trending`, `velocity`, `snapshot`, `export`                                                                   |
| `search`    | Initialize FTS/trie search, query feeds, and manage saved searches     | `query`, `autocomplete`, `init`, `embeddings`, `save`, `list-saved`                                                       |
| `recommend` | Generate recommendations and track recommendation events               | `get`, `track`, `weights`                                                                                                 |
| `monitor`   | Run the monitoring service and manage follows/digests                  | `start`, `stop`, `status`, `follow`, `unfollow`, `list-follows`, `subscribe-digest`, `unsubscribe-digest`, `list-digests` |
| `visualize` | Render topic taxonomy artifacts directly from `data/topics.yaml`       | `mermaid`, `json`, `stats`                                                                                                |
| `nlp`       | NLP maintenance commands with runtime-loaded heavy dependencies        | `quality`, `entities`, `sentiment`, `topics`, `scheduler`, `stats`                                                        |

## Core pipeline examples

### Curated catalog pipeline

```bash
uv run ai-web-feeds load from-yaml --input data/feeds.yaml --clear
uv run ai-web-feeds validate all
uv run ai-web-feeds enrich all \
  --input data/feeds.yaml \
  --output data/feeds.enriched.yaml \
  --schema data/feeds.enriched.schema.json
uv run ai-web-feeds export all --input data/feeds.enriched.yaml --output-dir data
uv run ai-web-feeds opml all --output data/all.opml
uv run ai-web-feeds opml categorized --output data/categorized.opml
```

### Runtime search and recommendations

```bash
uv run ai-web-feeds search init
uv run ai-web-feeds search query "llm agents" --type full_text --limit 10
uv run ai-web-feeds search autocomplete llm --limit 8
uv run ai-web-feeds recommend get --topics llm,agents --limit 10
```

### Test wrappers

```bash
uv run ai-web-feeds test all --coverage
uv run ai-web-feeds test unit --fast
uv run ai-web-feeds test file tests/tests/packages/ai_web_feeds/test_search.py -k semantic
uv run ai-web-feeds test markers
```

## Command details

### `process`

Use the root `process` command when you want one command to orchestrate load,
validation, enrichment, export, and persistence.

```bash
uv run ai-web-feeds process \
  --input data/feeds.yaml \
  --output data/feeds.enriched.yaml \
  --schema data/feeds.enriched.schema.json \
  --database sqlite:///data/ai-web-feeds.db
```

### `validate`

The current validation surface is subcommand-based.

```bash
uv run ai-web-feeds validate feeds --input data/feeds.yaml --strict
uv run ai-web-feeds validate topics --input data/topics.yaml --strict
uv run ai-web-feeds validate references --strict
uv run ai-web-feeds validate all --strict
uv run ai-web-feeds validate url "https://example.com/feed.xml" --timeout 30
uv run ai-web-feeds validate report --recent 20
```

### `export`

`export` works from authored YAML documents, while `opml` works from the runtime
database.

```bash
uv run ai-web-feeds export json --input data/feeds.yaml --output data/feeds.json
uv run ai-web-feeds export opml --input data/feeds.yaml --output data/feeds.opml
uv run ai-web-feeds export all --input data/feeds.yaml --output-dir data --prefix feeds
```

### `analytics`

The live CLI exposes summary, trending, velocity, snapshot, and CSV export
commands.

```bash
uv run ai-web-feeds analytics summary --date-range 30d
uv run ai-web-feeds analytics trending --limit 10 --date-range 30d
uv run ai-web-feeds analytics velocity --granularity weekly --date-range 90d
uv run ai-web-feeds analytics snapshot
uv run ai-web-feeds analytics export --output reports/analytics.csv --date-range 30d
```

### `visualize`

`visualize` works directly from the authored topic taxonomy and does not depend
on a separate optional taxonomy package.

```bash
uv run ai-web-feeds visualize stats --input data/topics.yaml
uv run ai-web-feeds visualize mermaid --input data/topics.yaml --output taxonomy.mermaid
uv run ai-web-feeds visualize json --input data/topics.yaml --output taxonomy.json
```

### `nlp`

The `nlp` command group is always registered in CLI help. Runtime-heavy model
dependencies are imported when a concrete NLP subcommand executes.

```bash
uv run ai-web-feeds nlp stats --database sqlite:///data/ai-web-feeds.db
uv run ai-web-feeds nlp quality --batch-size 50
uv run ai-web-feeds nlp scheduler status
```

### `monitor`

The `monitor` group uses the unified runtime database resolution and exposes
`--database` for status, follow, and digest management commands.

```bash
uv run ai-web-feeds monitor status --database sqlite:///data/ai-web-feeds.db
uv run ai-web-feeds monitor follow user-1 test-feed --database sqlite:///data/ai-web-feeds.db
uv run ai-web-feeds monitor list-digests user-1 --database sqlite:///data/ai-web-feeds.db
```

`monitor stop` remains a placeholder command and currently returns a
not-implemented exit code rather than stopping an external process.

## Runtime defaults

- The CLI resolves its database from `AIWF_DATABASE_URL`.
- The canonical SQLite filename is `data/ai-web-feeds.db`.
- A legacy `data/aiwebfeeds.db` file is still accepted for backwards
  compatibility.

```bash
export AIWF_DATABASE_URL=sqlite:///data/ai-web-feeds.db
uv run ai-web-feeds stats show --format json
```

## Choosing between the CLI and direct Python calls

Use the CLI when you want reproducible repo workflows, structured command
output, or automation-friendly commands. Use the Python API when you want to
compose catalog operations inside your own scripts or notebooks.
