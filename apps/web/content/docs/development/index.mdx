# Development Overview

AI Web Feeds is a hybrid monorepo with three distinct kinds of truth:

1. **Authored repository data** in `data/*.yaml` and `data/*.json`
2. **Runtime state** in SQLite, browser-local state, and optional backend services
3. **User-facing surfaces** across the CLI, web app, docs site, and GitHub automation

## Core surfaces

| Surface           | Primary paths                                            | What it owns                                                                                  |
| ----------------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Core runtime      | `packages/ai_web_feeds/src/ai_web_feeds/`                | config, models, storage, load/validate/export, enrichment, analytics, search, recommendations |
| CLI               | `apps/cli/ai_web_feeds/cli/commands/`                    | command UX and workflow entrypoints over the core runtime                                     |
| Web app           | `apps/web/app`, `apps/web/lib`, `apps/web/components`    | public catalog pages, anonymous user-scoped APIs, admin UI, docs rendering, LLM routes        |
| Data assets       | `data/`                                                  | canonical feed catalog, enriched catalog, topic taxonomy, schemas, OPML, validation scripts   |
| GitHub automation | `.github/`                                               | issue intake, validation, release workflows, additive gh-aw pilots                            |
| Quality harness   | `tests/`, root `pyproject.toml`, `apps/web/package.json` | pytest, coverage, Playwright, Vitest, lint/build checks                                       |

## Repository data flow

```mermaid
flowchart LR
    authored[data/feeds.yaml\ndata/topics.yaml] --> validate[data/validate_data_assets.py]
    validate --> enrich[data/feeds.enriched.yaml]
    validate --> web[/api/feeds + /api/topics]
    enrich --> runtime[(SQLite runtime store)]
    runtime --> search[FTS5 + trie + embeddings]
    runtime --> analytics[analytics snapshots / reports]
    runtime --> web
```

## Current package layout

```text
ai-web-feeds/
├── packages/ai_web_feeds/    # Core Python runtime
├── apps/cli/                 # Typer CLI package
├── apps/web/                 # Next.js + Fumadocs app
├── tests/                    # Pytest suites
├── data/                     # Canonical YAML/JSON/OPML assets
└── .github/                  # Workflows, prompts, issue forms, agents
```

## Runtime defaults that matter in development

- `data/feeds.yaml` is the authored source catalog.
- `data/topics.yaml` is the authored taxonomy.
- `data/feeds.enriched.yaml` is a derived repository asset.
- `data/ai-web-feeds.db` is the canonical runtime SQLite filename.
- Public web flows are anonymous and device-scoped; admin routes are the only
  authenticated surface.
