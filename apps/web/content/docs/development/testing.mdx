# Test Infrastructure

This page captures the test configuration that exists in the live repository
today, not historical wrappers or aspirational commands.

## Python test authority

The root `pyproject.toml` is the canonical source for pytest discovery, markers,
and baseline coverage settings.

The dedicated `tests/pyproject.toml` mirrors those discovery semantics so
`cd tests && uv run pytest` collects the same suite while also writing HTML
reports and timeout-managed output into `tests/reports/`.

### Discovery settings

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
python_files = ["test_*.py", "*_test.py"]
python_classes = ["Test*"]
python_functions = ["test_*"]
```

### Default pytest options

```toml
addopts = [
  "--strict-markers",
  "--strict-config",
  "--import-mode=importlib",
  "--cov=ai_web_feeds",
  "--cov-report=term-missing",
  "--cov-report=html",
  "--cov-report=xml",
  "-ra",
  "-vv",
]
```

### Registered markers

```toml
markers = [
  "benchmark: marks performance benchmark tests",
  "database: marks tests requiring database access",
  "e2e: marks tests as end-to-end tests",
  "integration: marks tests as integration tests",
  "network: marks tests requiring network access",
  "slow: marks tests as slow (deselect with '-m \"not slow\"')",
  "unit: marks tests as unit tests",
]
```

## Canonical Python commands

```bash
uv run pytest
uv run pytest -m unit
uv run pytest -m integration
uv run pytest -m benchmark
uv run pytest -m "not slow"
uv run pytest tests/tests/packages/ai_web_feeds/unit/test_storage.py -k sqlite
```

<Callout type="info" title="CLI wrapper vs direct pytest">
  The CLI still exposes <code>ai-web-feeds test ...</code> commands, but the most direct and stable documentation path for the current repository is
  <code>uv run pytest</code> plus the markers above.
</Callout>

## Web test stack

`apps/web/package.json` defines the current web runners:

```bash
pnpm --dir apps/web test           # Playwright smoke lane
pnpm --dir apps/web test:e2e       # Playwright smoke lane
pnpm --dir apps/web test:e2e:full  # Full browser/device matrix
pnpm --dir apps/web test:unit      # Vitest
pnpm --dir apps/web test:vitest    # Vitest watch/dev mode
pnpm --dir apps/web test:ui        # Playwright UI mode
pnpm --dir apps/web test:headed    # Headed Playwright
```

<Callout type="info" title="Playwright strategy">
  The repository defaults to a deterministic Chromium smoke lane with one worker and no server reuse. Set <code>PLAYWRIGHT_FULL_MATRIX=1</code> when you need the full browser/device matrix. Set <code>PLAYWRIGHT_USE_DEV_SERVER=0</code>
  to run against a production build instead of <code>pnpm dev</code> once the branch is build-clean.
</Callout>

## Docs and route health checks

When docs, navigation, or render paths move, use the web checks that the repo
already wires up:

```bash
pnpm --dir apps/web build
pnpm --dir apps/web lint:links
```

These catch:

- broken navigation or rendering regressions during Next.js build
- internal doc link drift
- LLM-route and content-tree changes that break route generation

## Suggested verification order

1. `uv run pytest`
2. targeted Python marker or file runs for the surface you changed
3. `pnpm --dir apps/web test:unit`
4. `pnpm --dir apps/web test:e2e`
5. `pnpm --dir apps/web build`
6. `pnpm --dir apps/web lint:links` when docs/routes/navigation changed
