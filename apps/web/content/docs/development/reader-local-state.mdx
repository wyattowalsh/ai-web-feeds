# Reader Local State

The reader lane keeps anonymous, device-scoped state in two layers:

1. **IndexedDB** remains the canonical store for article flags, annotations, preferences, and the offline sync queue.
2. **`localStorage` snapshot backup** stores a compact, versioned copy of reader state so the UI can recover when IndexedDB is unavailable, reset, or partially corrupted.

This page documents the current reader-local contract used by:

- `apps/web/lib/reader-local-state.ts`
- `apps/web/lib/use-reader-preferences.ts`
- `apps/web/lib/use-reader-timeline.ts`
- `apps/web/lib/keyboard-shortcuts.ts`

## Storage roles

| Layer                                          | Purpose                                                               | Notes                                                                                                         |
| ---------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| IndexedDB `articles`                           | Canonical article flags (`read`, `starred`, `archived`, bookmark tag) | `categories` mirror feed metadata, `tags` stay reader-local, and `lastModified` drives last-write-wins merges |
| IndexedDB `annotations`                        | Notes, highlights, and conflict markers                               | Conflict markers use stable `conflict:<articleId>` ids                                                        |
| IndexedDB `syncQueue`                          | Offline mutations awaiting replay                                     | Queue ids are deterministic per article/action                                                                |
| `localStorage` `aiwebfeeds.reader.local-state` | Versioned recovery snapshot                                           | Used for migrations, corruption recovery, and IDB resets                                                      |

## Snapshot format

The current snapshot format is **version 2**.

```json
{
  "version": 2,
  "updatedAt": 1735689600000,
  "preferences": {
    "theme": "system",
    "layout": "cards",
    "fontSize": 16,
    "fontFamily": "system-ui",
    "readingWidth": "medium",
    "showImages": true,
    "showSummaries": true,
    "markAsReadOnScroll": false,
    "updatedAt": 1735689600000
  },
  "articles": {
    "article-123": {
      "read": true,
      "starred": false,
      "archived": false,
      "bookmarked": true,
      "lastModified": 1735689600000
    }
  }
}
```

## Migration rules

Legacy snapshots are normalized on read before they are used by hooks or state helpers.

### Version 1 → Version 2

- `articleStateById` is renamed to `articles`
- legacy `bookmark` is normalized to `bookmarked`
- missing booleans fall back to `false`
- missing timestamps inherit the snapshot `updatedAt`
- missing preference fields are backfilled from the reader defaults

### Corruption recovery

- invalid JSON falls back to an empty version-2 snapshot
- invalid preference values are normalized back to the reader defaults
- missing or stale IndexedDB preferences are restored from the snapshot when the snapshot is newer
- failed preference writes still update the versioned backup so the reader can recover on the next load
- locally-created article stubs preserve `publishedAtMs` as `null` when the source never published a date

<Callout type="info" title="Why the snapshot exists">
  The reader should stay usable even when IndexedDB is blocked by private-browsing limits, browser corruption, or a store reset during development. The snapshot is intentionally small and only mirrors reader-local state.
</Callout>

## Conflict handling

Reader article mutations use **last-write-wins** based on `lastModified`.

- when both IndexedDB and the snapshot contain article state, the newer `lastModified` wins
- local mutations always enqueue a deterministic sync item in `syncQueue`
- when a mutation targets an article that no longer exists in IndexedDB and no article context is available, the mutation is still preserved in the snapshot
- that missing-context case creates a durable conflict annotation with id `conflict:<articleId>`

Conflict annotations are regular local notes so they can be listed beside any other
reader annotations. The current conflict reason is:

- `missing_remote_article` — local state exists, but the latest remote/article payload is unavailable

## Offline sync queue semantics

Reader actions write one queue item per article/action pair:

| Queue id pattern              | Type         | Meaning                   |
| ----------------------------- | ------------ | ------------------------- |
| `reader:<articleId>:read`     | `read`       | Latest read/unread intent |
| `reader:<articleId>:star`     | `star`       | Latest star intent        |
| `reader:<articleId>:archive`  | `archive`    | Latest archive intent     |
| `reader:<articleId>:bookmark` | `tag`        | Bookmark tag add/remove   |
| `annotation:<annotationId>`   | `annotation` | Annotation upsert/delete  |

The ids are deterministic so newer local writes overwrite older pending work for the
same action instead of accumulating duplicates.

## Timeline cache and sorting rules

The aggregate reader timeline is sorted on the client even if the server already sent
sorted data. The canonical order is:

1. `publishedAtMs` descending
2. `feedTitle` ascending for ties
3. `title` ascending for ties
4. `id` ascending for ties

Cached aggregate responses expire when `meta.expiresAt` is reached. The reader hook
automatically forces a refresh once that deadline passes so stale snapshots are not
held indefinitely in memory.

The `/api/feeds/posts/aggregate` route now advertises a `600s` shared cache window to
match the aggregate timeline cache TTL used by `apps/web/lib/feed-posts.ts`.

## Keyboard shortcut defaults

Reader defaults are sourced from the preferences schema so persistence and the runtime
manager stay aligned.

- `j` / `k` — next / previous article
- `m` — mark as read
- `s` — star
- `a` — archive
- `v` — open original
- `/` — search
- `g h`, `g s`, `g u`, `g a` — section jumps
- `?` — show shortcuts
- `[` — toggle sidebar
- `Ctrl+K` and `Meta+K` — focus search

The manager preserves explicit remaps while still backfilling new defaults that older
records did not know about.

## Practical maintenance rules

- keep snapshot migrations additive and idempotent
- prefer deterministic queue ids for local actions
- never silently discard a newer local mutation when IndexedDB and snapshot disagree
- keep recovery logic in hooks small: normalize inputs, prefer newer backups, then persist forward
