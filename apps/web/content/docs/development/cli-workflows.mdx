# CLI Integration in Workflows

Repository workflows should reuse the Python runtime and CLI rather than
re-implementing catalog logic in shell snippets.

## Principles

1. Use `uv run ai-web-feeds ...` for command groups that already exist.
2. Use `uv run python data/validate_data_assets.py` for repository data-asset
   validation.
3. Use `pnpm --dir apps/web ...` for web build and docs checks.
4. Keep YAML workflows declarative; keep business logic in Python or TypeScript.

## Current command mappings

| Workflow need                          | Preferred command                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------------------ |
| validate authored catalog              | `uv run python data/validate_data_assets.py`                                               |
| validate CLI/runtime catalog contracts | `uv run ai-web-feeds validate all --strict`                                                |
| load catalog into runtime DB           | `uv run ai-web-feeds load from-yaml data/feeds.yaml --clear`                               |
| enrich derived asset                   | `uv run ai-web-feeds enrich all --input data/feeds.yaml --output data/feeds.enriched.yaml` |
| export JSON + OPML                     | `uv run ai-web-feeds export all --input data/feeds.yaml --output-dir data`                 |
| inspect topic taxonomy                 | `uv run ai-web-feeds visualize stats --input data/topics.yaml`                             |
| inspect NLP pipeline coverage          | `uv run ai-web-feeds nlp stats --database sqlite:///data/ai-web-feeds.db`                  |
| web docs/render checks                 | `pnpm --dir apps/web build` and `pnpm --dir apps/web lint:links`                           |

## Example snippets

### Feed data validation

```yaml
- name: Validate repository data assets
  run: uv run python data/validate_data_assets.py

- name: Validate runtime catalog commands
  run: uv run ai-web-feeds validate all --strict
```

### Feed processing

```yaml
- name: Load curated catalog
  run: uv run ai-web-feeds load from-yaml data/feeds.yaml --clear

- name: Enrich derived catalog
  run: >
    uv run ai-web-feeds enrich all
    --input data/feeds.yaml
    --output data/feeds.enriched.yaml
```

### Export artifacts

```yaml
- name: Export JSON and OPML artifacts
  run: uv run ai-web-feeds export all --input data/feeds.yaml --output-dir reports/exports
```

### Search and analytics maintenance

```yaml
- name: Initialize search tables
  run: uv run ai-web-feeds search init

- name: Capture analytics snapshot
  run: uv run ai-web-feeds analytics snapshot

- name: Export analytics CSV
  run: uv run ai-web-feeds analytics export --output reports/analytics.csv --date-range 30d
```

### Taxonomy and NLP maintenance

```yaml
- name: Check taxonomy visualization inputs
  run: uv run ai-web-feeds visualize stats --input data/topics.yaml

- name: Inspect NLP pipeline coverage
  run: uv run ai-web-feeds nlp stats --database sqlite:///data/ai-web-feeds.db
```

### Docs checks

```yaml
- name: Build web app
  run: pnpm --dir apps/web build

- name: Check internal links
  run: pnpm --dir apps/web lint:links
```

<Callout type="warn" title="Avoid legacy forms">
  Prefer current subcommand forms such as <code>validate all</code>,<code>export all</code>, and <code>opml all</code> over older flag-only examples like <code>validate --all</code> or <code>opml export</code>.
</Callout>
