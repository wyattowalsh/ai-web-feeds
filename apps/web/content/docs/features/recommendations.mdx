# AI-Powered Recommendations

> **Status**: Backend-backed
> **Local behavior**: Shows an intentional unavailable state until `BACKEND_URL` points to the ai-web-feeds backend.

The recommendations page at `/recommendations` is wired to real backend routes and no longer pretends to be fully available in backend-free local mode. When the ai-web-feeds backend is configured, the page loads personalized suggestions and records recommendation interactions. When it is not configured, the page shows one explicit unavailable panel and routes people back to the catalog instead of failing noisily.

## Current Experience

### Recommendation List

When the backend is available, the page renders:

- ranked feed recommendations
- recommendation reasons such as `similar_topics`, `popular`, `discover`, and `similar_content`
- topic chips for steering the current slice
- feed actions for opening a result in `/feeds`, subscribing, or dismissing it

### Personalization Input

The web client creates a stable local `user_id` in `localStorage` and sends it with every recommendation request. Topic chips refine the current request without changing the page URL.

### Interaction Tracking

The UI records these interaction types:

- `view`
- `click`
- `subscribe`
- `dismiss`

The backend stores that feedback, updates the user profile, and uses it to avoid repeating previously followed or already-interacted feeds in later recommendations.

### Unavailable Fallback

If `BACKEND_URL` is missing or the backend is unavailable, `/recommendations` shows:

- a setup message explaining that personalization is optional
- a link to `/feeds?mode=catalog`
- a link to the deployment guide

That unavailable state is expected behavior in backend-free local development.

## Backend Contract

The web layer uses two backend-backed routes:

- `GET /api/recommendations`
- `POST /api/recommendations`

`GET /api/recommendations` forwards:

- `user_id`
- `topics`
- `limit`

`POST /api/recommendations` accepts:

```json
{
  "user_id": "user_123",
  "feed_id": "feed-abc",
  "interaction_type": "subscribe",
  "reason": "similar_topics"
}
```

When the backend is unavailable, the proxy returns:

```json
{
  "error": "Recommendations are unavailable until BACKEND_URL points to the ai-web-feeds backend.",
  "code": "FEATURE_UNAVAILABLE"
}
```

with HTTP `503`.

## Running With the Backend

Start the backend HTTP surface:

```bash
uv run uvicorn ai_web_feeds.web_api:app --host 127.0.0.1 --port 8001
```

Point the web app at it:

```bash
BACKEND_URL=http://127.0.0.1:8001
```

Once `BACKEND_URL` is set, the page switches from the unavailable state to live recommendations automatically.

## API Example

```typescript
const params = new URLSearchParams({
  user_id: "user_123",
  topics: "agents,llm",
  limit: "10",
});

const response = await fetch(`/api/recommendations?${params.toString()}`);
const payload = await response.json();

if (response.ok) {
  console.log(payload.recommendations);
}
```
