# AI-Powered Recommendations

> **Status**: Optional and backend-dependent
> **Navigation**: Removed from the primary product path
> **Requirement**: `BACKEND_URL`

Recommendations are still present in the repository, but they are no longer treated
as part of the default deployment promise. The primary product loop is now:

`catalog -> search -> reader -> analytics -> OPML export`

Recommendation routes remain available for environments that run the external Python
backend and want to experiment with anonymous, device-bound personalization.

## What still exists

- `GET /api/recommendations`
- `POST /api/recommendations`
- Anonymous identity binding for feedback and follow-through
- The `/recommendations` page for backend-enabled environments

## What changed

- Recommendations are no longer in the primary navigation.
- The default deployment does not rely on them.
- Docs for search, reader, analytics, and OPML export now describe the shipped
  product center instead.

## Deployment guidance

If you do not configure `BACKEND_URL`, recommendation APIs will return backend
configuration errors and should be considered disabled for that environment.

```bash
BACKEND_URL=http://localhost:8001
```

## Why this page still exists

The repository still contains recommendation code, tests, and contracts that can be
useful for:

- backend-enabled experiments
- local development of personalized features
- future work if a first-class in-repo backend ships later
