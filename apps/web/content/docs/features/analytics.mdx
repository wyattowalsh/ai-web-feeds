# Analytics Dashboard

> **Status**: Backend-backed
> **Local behavior**: Shows an intentional unavailable state until `BACKEND_URL` points to the ai-web-feeds backend.

The analytics surface at `/analytics` is now wired to real backend routes instead of placeholder APIs. When the optional backend is configured, the page loads summary metrics, trending topics, validation velocity, CSV export, and snapshots through the `/api/analytics/*` proxy layer. When the backend is not configured, the page shows a single deliberate unavailable panel instead of noisy card-level errors.

## What Ships Today

### Overview Dashboard

The main `/analytics` page reads from these backend-backed routes:

- `/api/analytics/summary`
- `/api/analytics/trending`
- `/api/analytics/velocity`
- `/api/analytics/export`
- `/api/analytics/snapshot`

The dashboard supports:

- **Time range filtering**: 7, 30, or 90 day slices
- **Topic focus**: Filter the overview by a topic string
- **Refresh**: Re-run the current query slice
- **CSV export**: Download the current summary slice as a CSV attachment

### Chart Stability

The comparison and forecasting routes remain useful exploratory surfaces:

- `/analytics/comparison`
- `/analytics/forecasts`

They now share the same Chart.js registration path as the rest of the app, which prevents the missing-controller runtime crashes that previously broke those pages in the browser.

### Unavailable Fallback

If `BACKEND_URL` is unset or unreachable, `/analytics` intentionally renders an unavailable state with:

- setup guidance
- a link back to `/feeds?mode=catalog`
- a link to the deployment guide

That fallback is now part of the product contract, not an implementation accident.

## Backend Contract

The web app expects the ai-web-feeds backend to expose:

- `GET /analytics/summary`
- `GET /analytics/trending`
- `GET /analytics/velocity`
- `GET /analytics/export`
- `POST /analytics/snapshot`
- `GET /analytics/snapshot`

When the backend is unavailable, the web proxy returns:

```json
{
  "error": "Analytics are unavailable until BACKEND_URL points to the ai-web-feeds backend.",
  "code": "FEATURE_UNAVAILABLE"
}
```

with HTTP `503`.

## Running With the Backend

Start the backend HTTP surface:

```bash
uv run uvicorn ai_web_feeds.web_api:app --host 127.0.0.1 --port 8001
```

Point the web app at it:

```bash
BACKEND_URL=http://127.0.0.1:8001
```

With that in place, `/analytics` switches from the unavailable panel to live metrics automatically.

## API Example

```typescript
const response = await fetch("/api/analytics/summary?date_range=30d&topic=llm");

if (response.status === 503) {
  const unavailable = await response.json();
  console.log(unavailable.code); // FEATURE_UNAVAILABLE
} else {
  const data = await response.json();
  console.log(data.total_feeds);
  console.log(data.validation_success_rate);
}
```
