# Analytics Dashboard

> **Status**: ✅ Live in the default deployment
> **Mode**: Local-first read-only analytics
> **Scope**: Catalog + recent post activity

The Analytics Dashboard now works without `BACKEND_URL`. It combines the checked-in
catalog with recent post timestamps gathered through the aggregate feed loader so
visitors can inspect what is publishing, which topics are most active, and which
sources are freshest in the current catalog slice.

Use `/feeds` first when you want to decide which part of the catalog matters.
Use `/analytics` when you want to understand what that catalog is publishing now.

## Features

### Key Metrics

- **Total sources**: Count of sources in the current catalog slice
- **Active sources**: Sources not marked inactive in the catalog
- **Posts in 24h**: Recent post count observed in the live analytics window
- **Posts in 7d**: Seven-day publication activity across the scanned source set
- **Topic count**: Number of distinct topics represented in the filtered catalog
- **Source type mix**: Distribution of source types across the filtered catalog
- **Scan coverage**: Explicit `matching_sources`, `scanned_sources`, `scan_limit`, `per_source_limit`, and `truncated` values for the live analytics window

### Interactive Charts

#### Most Active Topics

Bar chart showing recent post volume by topic, plus how many sources contribute to
each topic.

#### Publication Velocity

Time-series view showing recent publication timestamps bucketed by day, week, or month.

#### Freshest Sources

Panel listing the newest observed publishing sources in the active analytics window.

### Filtering

- **Time Range**: Last 7 days, 30 days, or 90 days
- **Topic Filter**: Limit the dashboard to a single topic slice
- **Refresh**: Re-run the local analytics fetch without leaving the page

### Data Export

- **CSV export**: Download the current analytics snapshot for external analysis
- **Summary API**: `/api/analytics/summary`
- **Trending API**: `/api/analytics/trending`
- **Velocity API**: `/api/analytics/velocity`

The summary payload includes `source_type_distribution` for the full filtered
catalog and `scan_summary` for the bounded live scan. CSV exports include both
sections so downstream consumers can distinguish catalog shape from scanned
activity coverage.

## Configuration

The public analytics dashboard does not require backend configuration. The current
implementation uses short-lived route caching to keep repeat visits fast.

```bash
# Optional: explicit site URL for metadata and production deployments
NEXT_PUBLIC_BASE_URL=https://aiwebfeeds.com

# Optional: external backend for non-core personalized routes only
BACKEND_URL=http://localhost:8001
```

## Usage

### Web Interface

Navigate to `/analytics` to access the dashboard.

Use the filter bar to change the date range, limit the view to a topic, refresh the
snapshot, or download a CSV export.

### CLI

```bash
# Runtime analytics summary
uv run ai-web-feeds analytics summary --date-range 30d

# Topic momentum
uv run ai-web-feeds analytics trending --limit 10 --date-range 30d

# CSV export
uv run ai-web-feeds analytics export --output reports/analytics.csv --date-range 30d
```

### API

```typescript
// Fetch analytics summary
const response = await fetch("/api/analytics/summary?date_range=30d&topic=llm");
const data = await response.json();

console.log(data.total_sources);
console.log(data.active_sources);
console.log(data.posts_last_24h);
console.log(data.source_type_distribution);
console.log(data.scan_summary);
```

```typescript
// Fetch trending topics
const trending = await fetch("/api/analytics/trending?date_range=30d&limit=10");
```

## Current limits

- The dashboard is built from the shipped catalog plus recent aggregate feed scans,
  not from a long-term analytics warehouse.
- Freshness, trending, and velocity panels disclose when the live scan window is
  truncated instead of silently implying exhaustive coverage.
- Topic momentum reflects recent publication timestamps, not embeddings or
  behavioral recommendation signals.
- Personalized analytics, recommendation attribution, and user-specific reporting
  remain backend-dependent and are not part of the default deployment.
