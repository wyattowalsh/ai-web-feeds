# Analytics Dashboard

> **Status**: Backend-backed
> **Local behavior**: Shows an intentional unavailable state until `BACKEND_URL` points to the ai-web-feeds backend.

The analytics surface at `/analytics` uses the real backend routes instead of placeholder APIs, but it is intentionally secondary to the reader-first product flow. When the optional backend is configured, the page loads summary metrics, trending topics, validation velocity, CSV export, and snapshots through the `/api/analytics/*` proxy layer. When it is not configured, the page shows one deliberate unavailable state instead of noisy card-level fetch failures.

## At a Glance

| Surface                                            | Uses backend            | Behavior when backend is unavailable                 |
| -------------------------------------------------- | ----------------------- | ---------------------------------------------------- |
| `/analytics` overview                              | Yes                     | Renders one intentional unavailable panel            |
| `/api/analytics/*` proxies                         | Yes                     | Returns `503 FEATURE_UNAVAILABLE`                    |
| `/analytics/comparison` and `/analytics/forecasts` | Not for route rendering | Continue to render with the shared Chart.js registry |

## What Ships Today

### Overview Dashboard

The main `/analytics` page reads from these backend-backed routes:

- `/api/analytics/summary`
- `/api/analytics/trending`
- `/api/analytics/velocity`
- `/api/analytics/export`
- `/api/analytics/snapshot`

The dashboard supports:

- **Time range filtering**: 7, 30, or 90 day slices
- **Topic focus**: Filter the overview by a topic string
- **Refresh**: Re-run the current query slice
- **CSV export**: Download the current summary slice as a CSV attachment

### Chart Stability

The comparison and forecasting routes remain exploratory surfaces:

- `/analytics/comparison`
- `/analytics/forecasts`

They now share the same Chart.js registration path as the rest of the app, which prevents the missing-controller runtime crashes that previously broke those pages in the browser.

### Unavailable State

If `BACKEND_URL` is unset or unreachable, `/analytics` intentionally renders one unavailable panel with:

- concise setup guidance
- a link back to `/?mode=catalog`
- a link to the deployment guide

That state is part of the product contract, not an implementation accident, and it should not overshadow the reader-first workflow.

## Proxy Contract

The web app expects the ai-web-feeds backend to expose the following routes:

| Web proxy                 | Backend route                                            | Purpose                                            |
| ------------------------- | -------------------------------------------------------- | -------------------------------------------------- |
| `/api/analytics/summary`  | `GET /analytics/summary`                                 | Summary KPIs for the selected date range and topic |
| `/api/analytics/trending` | `GET /analytics/trending`                                | Trending topic slice                               |
| `/api/analytics/velocity` | `GET /analytics/velocity`                                | Publication velocity data                          |
| `/api/analytics/export`   | `GET /analytics/export`                                  | CSV export                                         |
| `/api/analytics/snapshot` | `POST /analytics/snapshot` and `GET /analytics/snapshot` | Snapshot creation and latest snapshot retrieval    |

## Backend-Off Response

When the backend is unavailable, the web proxy returns:

```json
{
  "error": "Analytics are unavailable until BACKEND_URL points to the ai-web-feeds backend.",
  "code": "FEATURE_UNAVAILABLE"
}
```

with HTTP `503`.

## Local Smoke Test

Start the backend HTTP surface:

```bash
uv run uvicorn ai_web_feeds.web_api:app --host 127.0.0.1 --port 8001
```

Point the web app at it:

```bash
BACKEND_URL=http://127.0.0.1:8001
```

With that in place, `/analytics` switches from the unavailable panel to live metrics automatically.

Quick verification:

```bash
curl "http://127.0.0.1:3000/api/analytics/summary?date_range=30d&topic=llm"
```
