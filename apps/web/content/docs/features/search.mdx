# Search & Discovery

> **Status**: ✅ Live in the default deployment
> **Search model**: Local-first lexical ranking
> **Scopes**: `sources` and `articles`

The Search page is the query surface for the catalog after you know what kind of
slice you want. Use `/feeds` when you want to narrow the registry by browsing
and selection first, then switch to `/search` when you want text retrieval
across sources or recent articles.

The page searches either:

- **Sources**: catalog entries such as blogs, newsletters, repositories, and feeds
- **Articles**: recent post entries gathered through the aggregate feed loader

The public search routes work without `BACKEND_URL`. Optional backend-backed
features such as saved searches and analytics logging degrade safely when the
Python storage service is not configured.

## Features

### Unified Search Interface

Single search bar at `/search` with query-stateful filters and source/article
scope switching. It complements the feed catalog instead of replacing it.

### Source Search

Local lexical ranking across the checked-in catalog:

- **Searches**: title, description, notes, tags, source type, and topic labels
- **Filters**: `source_type`, `topics`, and `verified`
- **Ranking**: text matches first, with verified and active sources used as
  tie-breakers

When the goal is “find the exact feeds I want to export,” start in `/feeds` and
use search only after you know you need text retrieval rather than catalog
filtering.

### Autocomplete Suggestions

Autocomplete is also local-first:

- **Up to 5 matching feeds** from the checked-in catalog
- **Remaining topic slots up to the route limit**
- **Prefix-based suggestions** that trim input whitespace before matching

Route: `/api/search/autocomplete?prefix=<query>`

### Article Search

Article search uses the aggregate feed loader to scan recent posts from the most
relevant catalog sources, then ranks those posts lexically with freshness as a
tie-breaker.

Use it when you want to search what is publishing now rather than just the source
registry.

### URL-driven filters

The page keeps its search state in the URL so searches are shareable and reload
cleanly:

- `q`: normalized query string
- `scope`: `sources` or `articles`
- `source_type`: optional source-type filter
- `topics`: comma-separated topic ids
- `verified`: `true` or `false`

### Optional saved searches

Saved searches are still available as an optional storage-backed workflow:

- `GET /api/search/saved`
- `POST /api/search/saved`
- `DELETE /api/search/saved?id=<id>`

If `BACKEND_URL` is not configured, the route returns an unavailable payload
instead of breaking the main search experience.

## API

### Source search

```typescript
const response = await fetch("/api/search?q=agents&scope=sources&verified=true");
const data = await response.json();
```

### Article search

```typescript
const response = await fetch("/api/search?q=rag&scope=articles&topics=agents,llm");
const data = await response.json();
```

### Search analytics logging

```typescript
await fetch("/api/search", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    query: "agent systems",
    type: "full_text",
    filters: { search_type: "sources", verified: true },
    clicked_results: [],
    result_count: 12,
  }),
});
```

If the backend is unavailable, the page still searches locally and analytics logging
falls back to a non-fatal accepted response.

## Configuration

```bash
# Optional backend for saved searches and storage-backed search analytics
BACKEND_URL=http://localhost:8001
```

## Usage

### Web Interface

Navigate to `/search`:

1. Type query in search bar
2. Choose `Sources` or `Articles`
3. Apply source-type, topic, or verification filters
4. Share or revisit the URL to preserve the current search state
5. Save the search only if backend storage is configured

**Keyboard Shortcuts**:

- `Arrow keys`: Navigate autocomplete suggestions
- `Enter`: Execute search

### CLI

```bash
# Runtime lexical search
uv run ai-web-feeds search query "transformer attention" --limit 20

# Runtime semantic search remains a CLI/backend concern
uv run ai-web-feeds search query "machine learning" --type semantic --threshold 0.7

# Filter by source type and topic
uv run ai-web-feeds search query "pytorch" --source-type blog --topic training
```

## Current limits

- The public web experience does **not** run semantic retrieval by default.
- Article search scans recent aggregate posts, not a permanent article warehouse.
- Saved searches and some analytics logging remain storage-backed optional features.
