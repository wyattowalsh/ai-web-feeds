# Visualization & Analytics

The shipped visualization surface is a 2D topic graph and Chart.js analytics charts. Series stay on stored catalog rows. An empty series is `{ "demo": false, "points": [] }`.

Forecasts are not enabled. The custom chart builder is not enabled. The dashboard builder is not enabled. This guide does not add Redis, a device-id JWT, or a database migration.

## Topic graph

`GraphVisualizer` in `apps/web/components/graph-visualizer.tsx` draws an SVG graph with `d3`. It is not a WebGL or Three.js scene.

Layouts are `force`, `radial`, `tree`, and `circular`. The same component supports d3 drag and zoom.

It is used on:

- `/topics`, through `TopicGraph`
- `/explorer`, through `ExplorerClient`

`d3` is already a dependency of `apps/web`. Do not add a second graph or chart library for this view.

## Analytics charts

These analytics components import `chart.js` and `react-chartjs-2`:

- `VelocityChart` uses a line chart and requests `/api/analytics/velocity`
- `TrendingTopicsChart` uses a bar chart and requests `/api/analytics/trending`
- `HealthDistributionChart` uses a pie chart and reads `health_distribution` from `/api/analytics/summary`

`/api/analytics/summary` accepts `date_range` values `7d`, `30d`, and `90d` (anything else is treated as `30d`) and an optional `topic`. The summary object includes `demo: false`, `forecast_enabled: false`, and `ml: null`. It is not the points series below.

There is no separate chart library beside Chart.js.

## Series contract

When a series has no stored rows, the JSON body is:

```json
{ "demo": false, "points": [] }
```

That is the empty result of `catalogSeries` in `apps/web/lib/visualization/catalog-series.ts`, and of these routes when they have nothing to return:

- `GET /api/analytics/export`
- `GET /api/analytics/trending`
- `GET /api/analytics/velocity`
- `GET` and `POST /api/visualizations`
- `POST /api/visualizations/[id]/data`

`demo` stays `false` when points exist. Those points are stored catalog or validation rows, not a generated forecast. An `ml` object is copied only when the caller already supplied one. An empty catalog does not add `ml`.

On the Python visualization router, `POST /api/v1/visualizations/{id}/data` returns the same empty series when `AWF_VIZ_ENABLED` is unset or blank. A non-empty value only allows that route to return stored catalog points. It does not turn on forecasts or the dashboard builder.

## Not enabled

### Forecasts

Forecasts are not enabled. `/analytics/forecasts` says so. `ForecastService` returns `{ "enabled": false, "reason": "forecast is not enabled" }` and does not fit a model. Do not install a forecasting extra for this guide.

Forecast tables are not a user feature. This guide does not add a migration for them.

### Custom chart builder

The custom chart builder is not enabled. `/analytics/visualizations` keeps real catalog rows only, with `demo` false. Saved-chart editing, publication export, and a custom builder are not part of this setup.

### Dashboard builder

The dashboard builder is not enabled. Web dashboard routes respond with HTTP 501 and:

```json
{ "enabled": false, "reason": "dashboard builder is not enabled" }
```

Do not install or document a grid-layout builder. Dashboard tables are not a user feature. This guide does not add a migration for them.

## Getting started

### Prerequisites

- Python 3.13+ with uv
- Node.js with pnpm

Redis is not required. There is no device-id JWT to configure.

### Install

From the repository root:

```bash
uv sync
```

Chart.js is what the analytics charts import. From `apps/web`:

```bash
cd apps/web
pnpm add chart.js react-chartjs-2
```

Do not add `three`, `@react-three/fiber`, `@react-three/drei`, or `react-grid-layout`.

### Run the web app

```bash
cd apps/web
pnpm install
pnpm dev
```

Open `/topics` or `/explorer` for the 2D graph.
