The web has always been a firehose. For humans, social feeds and search engines act as rough filters. For AI agents, there's been no equivalent — just raw HTTP and hope.

That's what AI Web Feeds is for.

## The problem we kept running into

Every time we wired up an AI agent to consume live web content, the same friction appeared: scraping is brittle, HTML parsing is noisy, and paywalls break unexpectedly. Meanwhile, thousands of high-quality sites publish structured, well-formatted RSS and Atom feeds that almost nobody was cataloguing for machine consumption.

The existing feed directories (OPML archives, Feedly exports, random GitHub lists) weren't designed with programmatic access in mind. They lacked:

- **Consistent metadata** — categories, quality signals, update frequency
- **Validation** — are these feeds actually reachable and well-formed?
- **Taxonomy** — a coherent topic graph rather than a flat tag cloud
- **Machine-first formats** — JSON endpoints, LLM-friendly text renderings

So we built what we wanted to use.

## What the project ships

**A feed catalog** (`data/feeds.yaml`) with hundreds of curated entries across AI, software engineering, research, and adjacent technical domains. Every feed carries structured metadata validated against a JSON Schema.

**A topic taxonomy** (`data/topics.yaml`) with 400+ categories organised as a directed acyclic graph. Topics carry facets (type, domain, technical depth), relationships (parent, related, supersedes), and display metadata — enough for rich filtering and graph visualisation.

**AI-enriched metadata** (`data/feeds.enriched.yaml`) with quality scores, entity extractions, and sentiment signals generated by LLM pipelines over the actual feed content.

**A documentation site** (you're reading it) with interactive explorers, full-text search, and LLM-optimised endpoints at `/llms.txt` and `/llms-full.txt`.

**A Python library and CLI** for feed fetching, validation, enrichment, and export — so you can run the whole pipeline yourself.

## Who it's for

- **Developers** building retrieval-augmented generation (RAG) systems who need clean, reliable content streams
- **AI researchers** tracking the literature across arXiv, blogs, and newsletters
- **Tool builders** who want a structured, maintained feed catalog as a dependency rather than a one-off scrape

## Open source, open data

Everything is Apache 2.0. The feed data, the taxonomy, the scoring logic — all of it is in the repository and intended to be forked, extended, and contributed back to.

We're at v0.1.0 — early, but real. If you're building with feeds for AI, we'd love to hear what's missing.
